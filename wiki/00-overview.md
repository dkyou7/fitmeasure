> 이 폴더(`wiki/`)는 사람과 LLM이 이 프로젝트를 빠르게 이해하고 이어서 개발하기 위한 문서다.

> 새로운 세션에서 이 프로젝트를 만지기 전에 `00 → 01 → 02` 순서로 읽으면 된다.

## 한 줄 정의

헬스장(클럽)에서 트레이너가 회원의 운동력을 정형화된 데이터로 측정하고, 그 성장을 보여주는 **B2B2C 웹 서비스**. 브랜드명은 미정(코드상 `fitmeasure`, 화면 표기 "측정.").

## 핵심 컨셉 3가지

1. **측정 도구 제공자** — 우리는 "측정을 대신"하지 않는다. 헬스장이 자기 방식대로 측정·기록할 **도구**를 제공할 뿐이다. 측정 기준·가격은 헬스장이 정한다. (노션/에어테이블 포지션)

2. **한 사람이 여러 역할** — 사람(Member)과 역할(Membership.role)을 분리했다. 한 계정이 A헬스장 사장이면서 B헬스장 회원일 수 있다. 가입은 하나, 역할은 클럽과의 관계에 따라 붙는다.

3. **전화번호로 기록 통합** — 전화번호가 사람을 식별한다. 회원이 헬스장을 옮겨다녀도 같은 번호면 기록이 한 사람에게 피드처럼 쌓인다. (단, 클럽은 자기 클럽 기록만 본다 — 격리)

## 수익 모델

- 우리 → 헬스장: 회원 수 구간별 월 구독 (claim한 회원 10명까지 무료)
- 헬스장 → 회원: 사장 자유 (우리는 관여 안 함)
- **무료 한도 기준 = claim한(계정 만든) 회원 수.** 익명 측정은 무제한. 회원이 "내 기록 보고 싶다"고 가입할수록 유료 압력이 생기는 구조.

## 성장 엔진 (핵심 전략)

두 주체의 욕구 충돌을 이용한다:
- 사장은 무료 유지하려 익명으로 두고 싶어함
- 회원은 자기 기록을 누적·열람하고 싶어함 → claim(가입)

회원이 공유 카드를 받고 "내 기록으로 남기기"를 누르면 claim. claim한 회원은 사장이 못 치우고(카운트 확정), 회원이 가입할수록 유료로 넘어간다. **회원이 사장을 유료로 끌어올린다.**

## 기술 스택

- Spring Boot 4.1.1 / Java 21 / Maven
- Thymeleaf + Thymeleaf Layout Dialect + htmx (SPA 아님, 서버 렌더 + 부분 갱신)
- Bootstrap 5.3 (CSS만, JS 미사용) + 브랜드 색 오버라이드
- Chart.js (성장 추이 그래프)
- Spring Security (휴대폰→아이디 기반 로그인)
- JPA / Hibernate 7 · 개발 H2(MySQL 모드) / 운영 MySQL
- Lombok

## 현재 개발 상태 (요약)

돌아가는 전체 흐름: 가입 → 로그인 → 클럽 생성 → 회원 등록(전화번호) → 측정 → 결과·추이 → 공유 카드 → claim → 회원 피드.
권한 층위: 운영자(ADMIN) / 사장(OWNER) / 트레이너(STAFF) / 회원(MEMBER) / 떠도는 계정(USER).

상세는 `03-status-and-todo.md` 참고.
