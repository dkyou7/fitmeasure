# 구현 현황과 다음 할 일

## 구현 완료 (전체 흐름 동작)

**계정/인증**
- 회원가입(`/signup`) — 아이디+비번, 떠도는 계정 생성
- 로그인(`/login`) — 아이디 기반, 소셜 버튼은 목업(원형 아이콘)
- 클럽 없어도 로그인 가능(인증/소속 분리)

**클럽/역할**
- 클럽 생성(`/clubs/new`) — 설득형 랜딩 + 생성 폼, 생성 시 OWNER 자동 부여 + 표준 프로그램 복사
- 생성 직후 세션 clubId 미갱신 → **재로그인 안내**(MVP 타협)
- 권한 5층위 + 역할별 네비 분기

**측정 코어**
- 회원 등록(`/members`) — 전화번호 필수, 번호로 Member 통합, 동의 체크
- 프로그램 관리(`/programs`, `/programs/{id}`) — 여러 프로그램, 항목 인라인 편집(측정값 있으면 잠금)
- 측정 입력(`/measure/{mid}/program/{pid}`) — 프로토콜 노출, 태블릿 우선
- 결과지(`/measure/result/{id}`) — 직전 대비 변화, 성장 추이 그래프(기본 펼침)
- 대시보드(`/dashboard`) — 측정 명단(정상/임박/지연/이탈위험)

**공유/회원**
- 공유 카드(`/s/{token}`) — 익명 카드 + 잠긴 성장 그래프(갈증 유발), 로그인 시 "전체 기록 보기" 분기
- claim(`/s/{token}/claim`) — 아이디+비번으로 계정 생성
- 회원 피드(`/me`) — 여러 클럽 기록 시간순, 헬스장 개설 프로모션 배너(클럽 없는 사람만)
- 프로필(`/me/profile`) — 이름·닉네임 수정(연락처는 읽기전용)

**운영자**
- 플랫폼 관리(`/admin`) — 전체 클럽 목록, plan 수동 토글(수기 계약)

**공통**
- layout.html(앱), member-layout.html(회원), 독립 페이지들
- sticky 아닌 여백 footer, CSRF(htmx/fetch/form 전부), 브랜드 색

## 시드 계정 (local 프로파일)

- `admin` / `admin1234` — 운영자(클럽 없음)
- `owner` / `1234` — 데모 헬스장 사장
- `trainer` / `1234` — 데모 헬스장 트레이너
- 데모 클럽: "데모 헬스장"(slug: demo-gym), 표준 프로그램 2개 복사됨
